# Content quality rules

## Evidence

- Treat the user's supplied profile, notes, cases, documents, and links as the evidence boundary.
- Label interpretation as judgment, not as a verified project result.
- Ask for the minimum missing detail that would materially change the conclusion.
- Never invent employers, customers, project scale, conversion, revenue, engagement, accuracy, or time saved.

## Spoken delivery

- Open with a recognizable work scene, mistake, disagreement, or decision conflict.
- Use short sentences and concrete verbs.
- Explain technical concepts through decisions and consequences.
- Use transitions that sound natural when spoken aloud.
- End with one useful next action and at most one natural call to action.

## Platform adaptation

- Preserve the same thesis across platforms.
- Adapt title density, description length, tags, discussion question, and call to action.
- Produce only the platforms explicitly selected by the user.
- When the platform is unspecified, return a platform-neutral package or ask only if platform choice materially changes the result.
