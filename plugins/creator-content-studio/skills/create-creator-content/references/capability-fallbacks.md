# Capability fallbacks

## Search is unavailable

- Continue with creator-supplied facts and clearly label the result as an internal content judgment.
- Do not invent platform samples, popularity, dates, authors, engagement metrics, or direct quotes.
- Provide a short manual research checklist only when research would materially improve the result.

## A platform page is inaccessible

- Record that the sample could not be verified.
- Do not infer its contents from a search snippet alone when precise evidence is required.
- Use accessible primary sources or omit the sample.

## An attachment cannot be read

- Identify the attachment that could not be accessed.
- Continue with the readable inputs.
- Ask the user to reattach or paste only the section necessary for the next decision.

## File writing is unavailable

- Return complete Markdown or structured content in the response.
- Do not produce a fake path, download link, manifest, or success message.
- Tell the user what filename would be created when file access becomes available.
